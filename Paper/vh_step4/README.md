### 予算と仕様上の区別

- C1_budgeted/C4_budgetedは1回の行動決定につき、生成・レビュー・説明・再生成の4要求、合計出力上限1024tokensをそろえる。終了判定は別の1要求。レビューがYesでも再生成し、元の必要時のみ修正するC1と区別する。入力の長さ、実際の生成長、成功までの意思決定回数は異なり、厳密な総トークン一致対照ではない。個別プロンプト・各段の要求数・実消費を保存する。
- C3は失敗した行動も参照列長Lに対する2Lの総実行予算に含める。1回修復も失敗したら停止する。失敗によって変化した環境を元に戻したとは扱わず、再抽出後の知識とVH応答を再生成に渡す。成功した修正行動だけを保存列・次段の履歴に加える。CAPE等の忠実再現ではなく独自の実行後修復対照である。
- C5は8操作・16条件のみの記号検証であり、VHの到達可能性・物体の操作適合性・物理制約を網羅しない。完全グラフの空状態配列は既知の空集合と評価し、抽出知識で情報不足とするC2とは区別する。この意味論の差も含むため、C5との差をすべて「物体の抽出漏れ」に帰属させない。完全グラフはLLMに送らない。
- 元のMultiループと同じメッセージ・厳密なEnd判定・参照長0特例・上限到達時の停止を基本とした新しいドライバである。C3を追加するため旧NotebookのASTをそのまま実行したとは記載しない。C3以外で実行失敗が出れば元実装同様に終了する。
- 新ドライバのEnd時の成否は終了判定に渡した直前のグラフで判定し、終了後にもグラフを取得して独立にfinal_goalを保存する。元NotebookのEnd後の再取得時点と厳密に同じとは扱わない。すべての新条件に同じ規則を適用し、原稿の過去結果をこの判定で再分類しない。
- 検索は以前に保存した `Paper/nonvh/retrieval_selections.csv` を使う。randomのrepeat=0/1/2を実行の反復に対応させ、モデル間で同じ選択を使う。semanticは従来の保存済みMiniLM選択。名前の候補集合・最長列の採用規則は静的評価のまま。現時点で新しい埋め込みを呼ばない。
- 反復ごとにタスク・モデルのブロックとブロック内の条件順を乱数seed=20260907で並べ替え、順序をconfigに保存した。タスク数4（指示名3）なので反復を独立な12タスクとして推測統計を行わない。
