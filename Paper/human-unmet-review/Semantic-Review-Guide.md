# 未充足条件としての再確認：8件

今回の目的は、応答が「満たされていない前提条件」を正しく示しているかの確認です。応答文が現在状態と一致するかの採点とは異なります。記入済みの `review.csv` はそのまま保持し、再確認には **semantic_review.csv** を使ってください。採点は空欄から始め、旧ラベルを機械的に反転・転記しません。

## 各ケースの読み方

1. `Review.md` の同じ番号のケースで、候補行動、実際の要求に含まれる `Preconditions:`、現在状態を確認します。
2. 各前提条件を「満たす／満たさない／情報不足」に分けます。根拠では、モデルへの提示文から分かるのか、補助の抽出辞書・グラフから分かるのかも区別してください。部屋が同じという記述だけから、近接や保持を推測しません。
3. 「満たさない」条件と応答全文を比較します。未充足条件を挙げているか、充足済み条件を誤って挙げていないか、必要な未充足条件の抜けがないかを確認します。短い条件文は要求への回答として読み、必ずしも現在状態の断定として読みません。
4. `semantic_review.csv` の `review_label,evidence,evaluator,date` のみを記入します。それ以前の列は変更しないでください。

架空の例：前提条件が「扉がOPEN」、現在状態がCLOSED、応答が「扉がOPEN」の場合、現在状態とは一致しませんが、未充足のOPEN条件を示す応答としては整合します。逆に現在OPENなら、その条件を未充足として挙げることは整合しません。これは採点方法の説明であり、8件の正解ラベルを指定するものではありません。

| ラベル | 判断の目安 |
| --- | --- |
| 正しい | 未充足条件の列挙が妥当で、必要な条件の抜けもない。 |
| 一部正しい | 妥当な部分はあるが、誤った条件や必要な条件の欠落もある。 |
| 誤り | 説明の主要内容が未充足条件の特定として不適切である。 |
| 判断不能 | 提示資料を確認しても、妥当性を判断する情報が不足している。 |

根拠の記入例（形式のみ）：`前提条件：…／現在状態・出典：…／未充足条件：…／応答の一致・余分・抜け：…`。判断不能なら不足する情報を書いてください。VHで成功したかどうか自体を説明の正解ラベルにせず、条件辞書の充足と区別します。

## 記録上の扱い

同じ著者による採点基準説明後の再確認であり、独立した評価者の追加や盲検評価ではありません。旧票・今回の説明・再確認票を区別して保存します。8件の代表例の確認から、全候補の正解率や評価者間一致率は推定しません。

記入の形式検証は `python3 scripts/validate_unmet_review.py --semantic` で行えます。この検証器は採点の意味的正しさを自動判定しません。
