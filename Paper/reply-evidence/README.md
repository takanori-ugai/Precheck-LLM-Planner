# 回答書の根拠ログの事後照合

`Paper/P45_reply.tex` の改善に伴うオフライン監査です。既存の実験結果・人手票は変更していません。API・VHを実行せず、人手による再採点も行っていません。

リポジトリルートで再生成できます。

```sh
python3 scripts/audit_reply_evidence.py
```

## 代表候補の状態一致

`counterfactual_alignment.csv` は、元の候補判定に用いた `extracted_knowledge.graph_file` と、再実行の最後の `execution.before_graph` を比較します。`scripts/vh_fixed_initial.py` の既存の照合関数を使用し、記号状態一致に加え、全ノード位置差最大0.001、四元数距離最大0.0001を要求します。これは候補時点の事後照合であり、初期状態だけの照合ではありません。

再実行結果 `counterfactual.json` の `before_graph` は、生成コードが候補実行後の最後のグラフ要求を記録しているため、実行前のグラフとして使用していません。元ログの該当フィールドは変更せず、実行イベントに保存された前状態へのパスを採用しました。

8件のうち記号状態一致は6件、位置・姿勢を含む許容差内の一致は2件でした。保存されたVH成功6/8件自体は変更しませんが、全8件を元の候補と同一状態での反実仮想評価とは扱えません。条件付きで選んだ少数例でもあり、6/8を誤棄却率や母集団の推定値に用いません。既存の計画・報告書中の「反実仮想」という名称だけで状態一致を仮定しないでください。

選択の母集団は `precondition_labels.csv` の `stage == precondition` かつ `checker_accepts == False` の59件です。保存順に、タスクごとに異なるモデル・条件の組を最大3件選んでいます。選択8件は状態変化task6が3件、配置task1が2件、配置task65が3件で、51件は未選択です。C2/C5を含む均衡抽出ではありません。`selection.csv` は拡張子に反してJSON形式です。

## 人手票が対象にした応答

`review_phase_audit.csv` は人手票と候補をrun ID・stepで結合し、判定応答 `precondition` と別要求の違反条件応答 `unmet` を並べたものです。人手ラベル・根拠・評価者・日付は `human_review_completed.csv` の内容をそのまま転記しています。

配布済み票 `human_review_form.md` が示した採点対象は `precondition` 応答です。公式人手票は全8件「判断不能／情報が不十分」ですが、8件すべてに別の `unmet` 応答が保存されています。この人手票から違反説明が存在しない、説明品質が低い、説明の意味的正しさが検証された、とは結論できません。`unmet` 本文と対応する状態・プロンプトを対象にした人手確認は別途必要です。この監査による自動判定を人手採点に置き換えていません。

`verification.json` は集計値と参照した入力ファイル・照合コードのSHA-256を保存します。回答書以外の既存報告書には今回発見した制約が未反映のものがあります。本資料は、それらの成功数や採点値を改変するものではなく、解釈上の制約を追加するものです。
